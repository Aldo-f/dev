# Hermes WebUI Docker Deployment Plan (from session 2026-08-13)

## Problem Identified
- **Hermes WebUI** was running as a systemd service on the host (`app-hermes-webui.service`) at `0.0.0.0:8787`
- **Traefik route** (`web.hermes.dev.aldof.duckdns.org`) pointed to Docker container `hermes-webui:8787` which **didn't exist**
- **Result**: 502 Bad Gateway when accessing `https://web.hermes.dev.aldof.duckdns.org/`

## Solution: Deploy Hermes WebUI as Docker Container

This gives bare server access via volume mounts while integrating with Traefik.

### Required Changes (3 files)

#### 1. Add to `container_services` in Ansible
**File**: `ansible/roles/containers/defaults/main.yml`

```yaml
container_services:
  # ... existing entries ...
  # 02-ai-* -> AI services
  - name: 02-ai-hermes-webui
    runtime_dir: "/home/aldo/dev/02-ai-hermes-webui"
```

> **Note**: runtime_dir points to the source repo because the Dockerfile uses `COPY . /apptoo` and the compose uses `build: context: /home/aldo/dev/02-ai-hermes-webui`.

#### 2. Fix Docker Compose Template (use placeholders)
**File**: `templates/infra/02-ai-hermes-webui/docker-compose.yml`

```yaml
# Hermes WebUI — Docker Compose for infrastructure deployment
# Generated by 01-core-infra playbook — do not edit runtime copy directly

services:
  hermes-webui:
    build:
      context: __CORE_INFRA__/../02-ai-hermes-webui
      dockerfile: Dockerfile
    container_name: hermes-webui
    restart: unless-stopped
    expose:
      - "8787"
    networks:
      - traefik_net
    volumes:
      - __HOME__/.hermes:/home/hermeswebui/.hermes
      - __HOME__/workspace:/workspace
    environment:
      - HERMES_WEBUI_HOST=0.0.0.0
      - HERMES_WEBUI_PORT=8787
      - HERMES_WEBUI_STATE_DIR=/home/hermeswebui/.hermes/webui
      - HERMES_WEBUI_PASSWORD=${HERMES_WEBUI_PASSWORD}
      - HERMES_WEBUI_DEFAULT_WORKSPACE=/workspace
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8787/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 20s

networks:
  traefik_net:
    external: true
```

**Key fixes**:
- `__HOME__` placeholders instead of hardcoded `/home/aldo`
- `__CORE_INFRA__` for build context (resolves to `/home/aldo/dev/01-core-infra`)
- Added `HERMES_WEBUI_DEFAULT_WORKSPACE=/workspace`

#### 3. Disable systemd service (avoid port conflict)
```bash
sudo systemctl stop app-hermes-webui.service
sudo systemctl disable app-hermes-webui.service
```

### Why This Works for "Bare Server Access"
The Docker container provides **full bare server access** because:
1. **Volume mounts**: `/home/aldo/.hermes` → all Hermes config, sessions, credentials, skills
2. **Workspace mount**: `/home/aldo/workspace` → full filesystem access to dev directories
3. **UID/GID alignment**: `docker_init.bash` auto-detects host UID/GID from mounted volumes
4. **Host tools available**: The container inherits the host's PATH via `docker_init.bash` environment pass-through
5. **Same Hermes agent**: The container installs `hermes-agent` from the mounted source in editable mode

This is exactly how the TUI works — same `~/.hermes`, same workspace, same agent binary.
